Dev notes for implementation

  • Use SVG on the site, PNG only for export. SVGs scale cleanly at any viewport; PNGs are provided at 512×512 for LinkedIn, deck slides, or any raster context. Inline the SVG where color inheritance matters (e.g., swapping strokes on hover).
  • Never use the PNG where the SVG will do. The PNG export loses the vector crispness that is the whole point of the set.
  • -inv variants for dark bands only. Use the default on paper / white backgrounds; use -inv on --ink (#1A1A1A) backgrounds like the footer and closing CTA. Orange stays orange in both.
  • Stroke weights are intentional. Body strokes are 1.4 (thin connective lines) or 1.75 (containers and primary geometry). Don't normalise them — the weight variance is what gives the set its editorial feel.
  • No lime in icons. The icon palette is charcoal + orange + white only. Lime is reserved for buttons, statements, and backgrounds — keeping the icon layer calm lets the lime moments land harder.
  • Source of truth: SVG files in assets/icons/. Regeneration script at /website-refinement-scripts/make_icons.py. If you tweak one, re-run the script so the PNG export stays in sync.
  • Batch 03 next if you want them: Step 03 compound stair-step illustration, and the dashboard-tile cluster replacing the gear graphic.
